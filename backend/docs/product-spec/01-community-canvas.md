# 1. 커뮤니티 캔버스

## 기획 의도

커뮤니티 캔버스는 네모닉의 출력된 메모 특성을 가장 직관적으로 보여주는 핵심 대표 콘텐츠이자 사이트 내
단일 공용 벽이다. 사용자는 새 메모를 작성하거나 릴레이 드로잉, 오늘의 운세, 플립북, 무한 캔버스 등
다른 부스에서 만든 결과물을 메모지로 출력해 벽에 자유롭게 부착한다.

방문자는 이 벽에서 타인의 자랑거리를 방명록처럼 감상한다. 결과물이 곧 공간이 되므로 별도 갤러리 없이
벽 자체가 전시 공간 역할을 한다.

## 핵심 재미 요소

- 내가 쓴 메모가 3D 공간에 남는 경험
- 메모를 어디에 붙일지 선택하는 인터랙션
- 벽이 점점 채워지며 살아 있는 느낌
- 다른 사용자의 메모를 건드리면 팔락이는 물리적 반응

## 1차 개발 범위

프론트엔드 디자인과 연동을 먼저 안정화하기 위해 1차 범위는 커뮤니티 메모의 기본 CRUD와 50개 FIFO 정책에
집중한다.

포함 범위:

- 공용 벽 메모 목록 조회
- 메모 상세 조회
- 직접 작성 메모 생성 및 부착
- 갤러리 결과물 메모 생성 및 부착
- 본인 메모의 위치, 회전, z-index, 데코레이션 수정
- 본인 메모 삭제
- 새 메모 생성 시점의 50개 FIFO 자동 정리

후속 범위:

- 신고 기능
- AI 모더레이션 실제 연동
- 백오피스 숨김 메모 검토, 복원, 삭제
- 실시간 벽 동기화

기본 CRUD/FIFO 단계에서는 WebSocket을 사용하지 않는다. 메모 생성, 수정, 삭제 후 프론트가 목록을 다시
조회하는 방식으로 화면을 갱신한다. 다른 사용자가 붙인 메모가 즉시 반영되는 라이브 벽 경험이 필요해지는
시점에 WebSocket 또는 SSE를 후속으로 검토한다.

## 메모 생명주기

- 캔버스 벽은 최대 50개의 메모를 유지한다.
- 새 메모가 부착되어 한도를 초과하면 가장 오래 부착된 메모부터 순차 제거한다.
- 제거 정책은 FIFO이다.
- 메모는 시간 제한 없이 벽에 남아 있으며, 갯수 기반 정책만 적용한다.
- 제거 임박 메모, 예를 들어 가장 오래된 5개에는 색 바램, 투명도 변화 등 퇴장 연출을 적용할 수 있다.
- FIFO로 제거된 메모는 DB에서 하드 삭제하지 않는다.
- FIFO 제거 시 `deleted_at`을 기록하고 `deleted_reason = expired`로 소프트 삭제한다.
- FIFO 갯수 검증은 메모 CREATE, 즉 부착 시점에만 실행한다.
- 사용자 삭제, 운영자 숨김 해제, 운영자 복원 등 다른 경로에서는 별도 갯수 검증을 하지 않는다.
- 복원 등으로 일시적으로 51개 이상이 되어도 다음 CREATE 시점에 FIFO가 자연스럽게 정리한다.
- 부적절 콘텐츠의 장기 잔존 리스크는 신고 5회 자동 숨김과 AI 모더레이션으로 보완한다.
- 숨김 상태 메모는 벽 렌더링에서 제외되며 갯수 한도 50개 카운트에도 포함하지 않는다.

## 사용자 인증 및 소유권

서비스는 회원가입과 로그인 없이 운영한다. 사용자 식별은 클라이언트 측 익명 UUID 기반이다.

| 항목 | 정책 |
| --- | --- |
| 식별자 생성 | 최초 방문 시 고유 UUID 생성 |
| 주 저장소 | `localStorage`에 UUID 저장 |
| 보조 저장소 | `cookie`에 동일 UUID 백업 저장 |
| 서버 연동 | 기존 익명 사용자 UUID를 `Anonymous-User-UUID` 요청 헤더로 전달 |
| 소유권 확인 | 데코레이션 수정, 배치 수정, 삭제 요청 시 헤더 UUID와 작성자 UUID 대조 |

### 소유권 정책

- UUID가 유효한 동안에만 본인 메모의 데코레이션 수정, 배치 수정, 삭제가 가능하다.
- 출력된 본문, 즉 텍스트, 드로잉, 불러온 결과물 원본은 수정할 수 없다.
- 색칠, 스티커, 꾸미기 등 데코레이션 레이어만 추가, 수정, 삭제할 수 있다.
- 벽 위 배치 정보인 `position_x`, `position_y`, `z_index`, `rotation_deg`는 본인 메모에 한해 수정할 수 있다.
- 데코레이션 데이터는 프론트가 정의한 JSON 덩어리로 저장하며, 백엔드는 내부 구조를 해석하지 않고 그대로 저장하고 반환한다.
- 시간 제한은 없으며, FIFO로 제거되기 전까지 데코레이션 수정이 가능하다.
- 브라우저 캐시 또는 데이터를 삭제하면 소유권을 잃는다.
- 소유권을 잃은 메모는 데코레이션 수정이 불가능하다.
- 고아 메모도 FIFO 한도 정책으로 제거되므로 영구 잔존하지 않는다.

### 모바일 환경

| 환경 | 동작 | 비고 |
| --- | --- | --- |
| 모바일 일반 브라우저 | `localStorage`와 `cookie` 모두 정상 동작 | Safari ITP로 저장소가 만료되어도 FIFO로 고아 메모 누적 없음 |
| 인앱 브라우저 | 외부 브라우저로 리다이렉트 | 공통 정책 참고 |
| 시크릿/프라이빗 모드 | 브라우저 종료 시 저장소 초기화 | 세션 종료 후 소유권 상실 |
| PC와 모바일 교차 사용 | 기기별 UUID가 달라 교차 수정 불가 | 회원가입 없는 구조의 한계로 수용 |

## 메모 소스와 저장 방식

커뮤니티 메모 생성은 하나의 생성 흐름에서 처리하되, 요청의 `sourceType`으로 직접 작성 메모와 갤러리 결과물
게시를 구분한다.

| sourceType | 설명 | 요청 식별자 | 저장 방식 |
| --- | --- | --- | --- |
| `DIRECT` | 커뮤니티에서 직접 자유 글쓰기/드로잉으로 만든 메모 | `fileId` | `community_memo.body_image_url`에 업로드된 이미지 object key 저장 |
| `GALLERY` | 갤러리에 저장된 다른 부스 결과물 또는 휴대폰 그리기 결과물 | `galleryId` | `community_memo.artifact_id`에 원본 artifact 연결 |

### 직접 작성 메모 업로드

직접 작성 메모 이미지는 기존 파일 공통 컴포넌트를 사용한다.

1. 프론트는 사용자가 완성한 메모를 이미지 파일로 만든다.
2. `POST /api/v1/files/presign`에 `purpose = COMMUNITY`로 업로드 URL을 요청한다.
3. 프론트는 발급받은 presigned URL로 MinIO에 이미지를 직접 업로드한다.
4. `POST /api/v1/files/{fileId}/confirm`으로 업로드 완료를 확정한다.
5. 커뮤니티 메모 생성 API에는 `sourceType = DIRECT`와 `fileId`를 전달한다.

커뮤니티 생성 API는 업로드 완료 상태이고 요청 UUID가 소유한 `COMMUNITY` 파일만 직접 작성 메모로 사용할 수
있다.

### 갤러리 결과물 게시

갤러리 결과물은 원본 `artifact`를 수정하거나 복사하지 않고, 커뮤니티 게시 복사본인 `community_memo`만 새로
생성한다.

- 사용자는 갤러리 결과물을 그대로 벽에 붙일 수 있다.
- 사용자는 갤러리 결과물에 데코레이션을 추가한 뒤 벽에 붙일 수 있다.
- 같은 갤러리 결과물을 여러 번 붙일 수 있다.
- 같은 원본 결과물을 한 번은 그대로, 한 번은 다른 데코레이션으로 꾸며서 붙일 수 있다.
- 갤러리 항목 삭제, 커뮤니티 게시 복사본 삭제, FIFO 삭제는 원본 `artifact`와 MinIO 원본을 삭제하지 않는다.

### 이미지 URL 응답 정책

DB에는 MinIO object key 또는 기존 artifact URL 문자열을 저장한다. API 응답에서는 프론트가 바로 렌더링할 수
있도록 public URL을 함께 내려준다.

- 직접 작성 메모는 `community_memo.body_image_url`의 object key를 public URL로 변환해 반환한다.
- 갤러리 게시 메모는 artifact 종류별 대표 이미지 URL을 반환한다.
- public URL 생성은 MinIO 파일 존재 확인이나 presigned URL 재발급 없이 설정값과 저장된 경로를 조합한다.

## 사용자 흐름

### 직접 작성 메모를 붙이는 흐름

1. 사용자가 커뮤니티 캔버스 존에 진입한다.
2. 프론트는 사용자의 익명 UUID를 확인하고, 없으면 신규 익명 사용자 UUID를 발급한다.
3. 사용자가 자유 글쓰기 또는 드로잉으로 새 메모를 만든다.
4. 프론트는 완성된 메모를 이미지 파일로 변환한다.
5. 프론트는 파일 공통 API로 `COMMUNITY` 목적의 presigned URL을 발급받고 이미지를 업로드한다.
6. 프론트는 업로드 confirm을 완료한다.
7. 사용자는 선택적으로 데코레이션을 추가한다.
8. 사용자는 대형 캔버스 벽의 원하는 위치를 선택한다.
9. 프론트는 `sourceType = DIRECT`, `fileId`, 위치, 회전, z-index, 데코레이션을 포함해 메모 생성 API를 호출한다.
10. 서버는 새 메모를 생성하고, 보이는 메모가 50개를 초과하면 가장 오래 부착된 메모부터 `expired`로 소프트 삭제한다.
11. 프론트는 생성 응답 또는 목록 재조회 결과로 벽을 다시 렌더링한다.

### 갤러리 결과물을 그대로 붙이는 흐름

1. 사용자가 커뮤니티 캔버스에서 갤러리를 연다.
2. 프론트는 내 갤러리 목록을 조회한다.
3. 사용자가 릴레이 드로잉, 오늘의 운세, 플립북, 무한 캔버스, 휴대폰 그리기 등 결과물 하나를 선택한다.
4. 사용자는 별도 데코레이션 없이 벽의 원하는 위치를 선택한다.
5. 프론트는 `sourceType = GALLERY`, `galleryId`, 위치, 회전, z-index, 빈 데코레이션을 포함해 메모 생성 API를 호출한다.
6. 서버는 요청 UUID가 해당 갤러리 항목의 소유자인지 확인한다.
7. 서버는 원본 artifact를 공유하는 새 `community_memo`를 생성한다.
8. 서버는 새 메모 생성 후 50개 FIFO를 처리한다.
9. 프론트는 목록을 다시 조회해 벽을 렌더링한다.

### 갤러리 결과물을 꾸민 뒤 붙이는 흐름

1. 사용자가 갤러리에서 결과물을 선택한다.
2. 프론트는 선택한 결과물을 메모지 형태로 보여준다.
3. 사용자는 스티커, 테두리, 낙서 등 데코레이션을 추가한다.
4. 사용자는 벽의 원하는 위치를 선택한다.
5. 프론트는 `sourceType = GALLERY`, `galleryId`, 위치, 회전, z-index, 데코레이션 JSON을 포함해 메모 생성 API를 호출한다.
6. 서버는 원본 artifact는 변경하지 않고, 커뮤니티 게시 복사본에만 데코레이션 JSON을 저장한다.
7. 같은 갤러리 결과물을 다시 선택하면 다른 위치와 다른 데코레이션으로 한 번 더 게시할 수 있다.

### 붙인 뒤 수정하는 흐름

1. 사용자가 벽에 붙은 메모를 선택한다.
2. 목록 또는 상세 응답의 `ownedByMe = true`인 경우 프론트는 수정과 삭제 UI를 제공한다.
3. 사용자는 위치, 회전, z-index, 데코레이션을 수정한다.
4. 프론트는 수정된 필드만 메모 수정 API로 전송한다.
5. 서버는 요청 UUID가 메모 작성자인지 확인한 뒤 전달받은 필드만 갱신한다.
6. 원본 이미지, 원본 artifact, 작성자, 부착 시각은 수정하지 않는다.

### 본인 메모를 삭제하는 흐름

1. 사용자가 본인 메모를 선택한다.
2. 프론트는 삭제 확인 UI를 제공한다.
3. 사용자가 삭제를 확정하면 프론트는 메모 삭제 API를 호출한다.
4. 서버는 요청 UUID가 메모 작성자인지 확인한다.
5. 서버는 메모를 하드 삭제하지 않고 `deleted_at`과 `deleted_reason = user_delete`를 기록한다.
6. 직접 작성 메모 이미지, 원본 artifact, MinIO 파일은 삭제하지 않는다.
7. 프론트는 목록을 다시 조회해 삭제된 메모를 벽에서 제거한다.

## 주요 기능

- 자유 글쓰기와 드로잉을 지원한다.
- 갤러리에서 릴레이 드로잉, 오늘의 운세, 플립북, 무한 캔버스 등 각 부스 결과물을 불러올 수 있다.
- 갤러리 결과물을 데코레이션 없이 바로 붙일 수 있다.
- 갤러리 결과물에 데코레이션을 추가한 뒤 붙일 수 있다.
- 게임 완료 결과물은 갤러리에 자동 저장된다.
- 같은 갤러리 아이템을 여러 번 게시할 수 있다.
- 게시된 각 메모 복사본은 독립적으로 FIFO, 신고, 삭제 정책을 적용받는다.
- 출력된 본문은 수정 불가이며, 출력 후 꾸미기 레이어만 수정 가능하다.
- 사용자는 메모 부착 위치를 자유롭게 선택한다.
- 본인 메모는 소유권이 유효한 동안 데코레이션 레이어 수정, 배치 수정, 삭제가 가능하다.
- 가려진 내 메모 찾기 기능을 제공한다.
- 타인 메모는 읽기와 터치 반응만 가능하며 수정 및 이동은 불가하다.
- 신고 기능을 제공한다.
- 신고 5회 누적 시 `is_hidden = true`로 자동 숨김 처리한다.
- 운영자는 백오피스에서 숨김 메모를 검토해 복원하거나 `deleted_reason = admin_removed`로 소프트 삭제한다.

## 조회 응답 정책

### 목록 조회

공용 벽 목록은 프론트가 추가 상세 조회 없이 벽을 기본 렌더링할 수 있도록 필요한 필드를 함께 반환한다.

조회 조건:

- `deleted_at IS NULL`
- `is_hidden = false`
- 정렬은 `z_index ASC`, 동률이면 `attached_at ASC`

대표 응답 필드:

- `memoUuid`
- `authorNickname`
- `sourceType`
- `memoImageUrl`
- `positionX`
- `positionY`
- `zIndex`
- `rotationDeg`
- `ownedByMe`
- `attachedAt`

목록 응답에는 작성자 UUID를 노출하지 않는다. 프론트가 내 메모 여부를 쉽게 판단할 수 있도록 요청자의
`Anonymous-User-UUID`와 메모 작성자가 같으면 `ownedByMe = true`를 반환한다.

### 상세 조회

상세 조회는 목록 필드에 더해 메모 관리와 편집에 필요한 자세한 정보를 반환한다.

대표 응답 필드:

- `decoration`
- `artifactId`
- `galleryContentKind`
- `moderationStatus`
- `reportCount`
- `createdAt`
- `updatedAt`

### 수정 요청

메모 수정은 본인 메모에 한해 부분 수정 방식으로 처리한다. 프론트가 보낸 필드만 갱신하고, 누락된 필드는 기존
값을 유지한다.

수정 가능 필드:

- `positionX`
- `positionY`
- `zIndex`
- `rotationDeg`
- `decoration`

수정 불가 필드:

- 직접 작성 메모의 원본 이미지
- 갤러리에서 가져온 원본 결과물
- 연결된 `artifact`
- 작성자
- `attachedAt`

## AI 모더레이션

사용자 흐름은 출력, 꾸미기, 벽 부착으로 동기 차단 없이 완료한다. 부착 직후 서버에서 비동기로 OCR과 혐오 표현
분류를 수행한다.

### 검사 파이프라인

1. Naver CLOVA OCR로 메모 이미지를 분석해 텍스트를 추출한다.
2. 추출 텍스트를 Unsmile 또는 동등 수준의 한국어 혐오 표현 분류 모델에 전달한다.
3. 여성/가족 혐오, 남성 혐오, 성소수자 혐오, 인종/국적 혐오, 연령 혐오, 지역 혐오, 종교 혐오, 기타 혐오,
   악플/욕설 등 카테고리를 분류한다.

### 처리 정책

- 일반 텍스트와 드로잉 도구로 그려 쓴 글자는 모두 OCR 대상이다.
- 이미지 내용 자체, 그림, 일러스트의 시각적 표현은 판정하지 않는다.
- OCR로 추출된 텍스트만 혐오 표현 분류 대상이다.
- 순수 그림은 OCR 결과가 비어 자연스럽게 통과된다.
- 플립북 GIF는 멀티프레임 애니메이션 특성상 OCR 검사 대상에서 제외된다.
- 플립북 GIF는 신고 5회 자동 숨김 정책만 적용한다.
- 부적절 표현이 감지되면 `is_hidden = true`, `hidden_reason = ai_moderation`으로 자동 숨김한다.
- 작성자 본인 캔버스/갤러리 보기에는 “부적절한 표현이 감지되어 게시가 보류되었어요” 안내를 표시한다.
- 부착 시점에 동기 차단하지 않는 이유는 이미 만든 메모를 폐기하는 경험 훼손을 피하기 위해서다.
- OCR 지연 중 잠시 노출될 수 있는 리스크는 신고 정책과 병행해 보완한다.

### DB 저장과 상태 전이

- OCR 원문 텍스트는 `community_memo.ocr_text`에 평문으로 저장한다.
- 분류 결과 라벨, 점수, 모델 메타데이터는 `community_memo.ocr_categories`에 JSON 문자열로 저장한다.
- 검사 완료 시각은 `moderation_checked_at`에 기록한다.
- 메모 INSERT 직후 `moderation_status = pending`으로 시작한다.
- AI 검사 통과 또는 운영자 복원 시 `moderation_status = allowed`로 전이한다.
- AI 차단 판정 시 `moderation_status = blocked`로 전이하고, 동시에 `is_hidden = true`, `hidden_reason = ai_moderation`, `hidden_at = NOW()`를 세팅한다.
- 신고 5회 누적 자동 숨김은 AI 판정과 직교하므로 `moderation_status`를 변경하지 않는다.
- 플립북 GIF 게시 메모는 OCR 검사 대상에서 제외하므로 INSERT 시점에 `moderation_status = allowed`로 세팅하고 비동기 모더레이션 작업을 등록하지 않는다.

### 모더레이션 호출 흐름

- 모더레이션은 외부 REST API로 사용자나 백오피스에 노출하지 않는다.
- Spring BE는 메모 INSERT 직후 `@Async` 또는 메시지 큐로 비동기 작업을 등록한다.
- 워커는 사내망 FastAPI 모더레이션 서비스의 `POST /check`를 호출한다.
- 요청 body 예시는 `{ "imageUrl": "...", "memoId": "..." }`이다.
- 워커는 결과를 받아 `community_memo`의 OCR/분류/상태/숨김 관련 컬럼을 업데이트한다.
- FastAPI는 사용자 클라이언트와 백오피스가 직접 호출하지 않으며, VPC/사설망에서만 접근 가능하다.

### 신고와 병행

- AI 모더레이션과 신고 5회 누적은 모두 `is_hidden = true`로 전환한다.
- `hidden_reason`은 `ai_moderation` 또는 `report_threshold`로 구분한다.
- 백오피스 검토 큐에서 사유별 분리 조회가 가능해야 한다.

### 오탐과 운영 모니터링

- 자동 숨김 오탐이 발생할 수 있다.
- 별도 사용자 이의 제기 채널은 두지 않는다.
- 운영자가 백오피스에서 복원하면 다시 노출된다.
- 자동 숨김 로그는 UUID, 원본 이미지, OCR 추출 텍스트, 감지 카테고리, 부착 시각, 검사 완료 시각, 검사 지연 시간을 포함한다.
- 오탐 비율은 OCR과 혐오 표현 분류 모델 임계값 조정에 참고한다.

## 신고 정책

| 항목 | 정책 |
| --- | --- |
| 신고 대상 | 캔버스 벽에 부착된 모든 메모 |
| 신고 방식 | 메모 터치 후 신고 버튼 노출, 신고 사유 선택 |
| 신고 사유 | 부적절 콘텐츠, 스팸, 그 외 |
| 중복 신고 방지 | 동일 UUID로 같은 메모 중복 신고 불가 |
| 자동 숨김 기준 | 신고 5회 누적 |
| 숨김 방식 | DB 삭제가 아니라 `is_hidden = true`로 전환 |
| 본인 메모 신고 | 불가, 본인은 직접 삭제 가능 |

### 숨김 후 처리

- 운영자는 숨김된 메모를 백오피스에서 검토한다.
- 악성 신고로 판단되면 `is_hidden = false`로 복원한다.
- 실제 부적절하면 `deleted_at`, `deleted_reason = admin_removed`로 소프트 삭제한다.
- 복원 시 캔버스가 50개를 초과할 수 있으나 즉시 다른 메모를 삭제하지 않는다.
- 다음 새 메모 부착 시 FIFO가 초과분을 정리한다.
- 운영자 검토 이력은 `reviewed_at`, `reviewed_by`, 복원/삭제 결정을 별도 감사 로그에 남긴다.

## 삭제 사유

| 값 | 의미 |
| --- | --- |
| `expired` | 갯수 한도 50개 초과로 FIFO 자동 소프트 삭제 |
| `admin_removed` | 운영자 검토 후 부적절 콘텐츠 소프트 삭제 |
| `user_delete` | 본인 직접 소프트 삭제 |

- 숨김 상태 메모는 FIFO 삭제 경로를 타지 않는다.
- 숨김 상태 메모는 운영자 검토 후 삭제될 때만 `admin_removed`로 기록된다.
- 백오피스 통계에서 삭제 사유별 비율을 확인할 수 있어야 한다.

## 인터랙션 연출

- 메모 부착 시 점착 사운드와 부착감을 제공한다.
- 터치 시 종이 팔락임을 연출한다.
- 그림자와 모서리 흔들림으로 종이의 깊이감을 표현한다.
- 겹쳐 붙인 메모의 레이어감과 그림자를 표현한다.
- 가까이 가면 메모가 살짝 들썩이며 읽기 가능 상태를 암시한다.
- 이동하거나 떼어낼 때 종이가 벗겨지는 사운드를 제공한다.

## 결과물 처리

커뮤니티는 결과물이 곧 공간이 되는 구조이다. 별도 갤러리 없이 벽 자체가 전시 공간이다. 갯수 기반 FIFO로
캔버스는 항상 최대 50개의 메모로 풍성한 상태를 유지하며, 새 메모가 부착될 때 오래된 메모가 순차적으로
물러난다.
