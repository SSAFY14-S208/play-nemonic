# 2. 우당탕 릴레이 드로잉

## 기획 의도

갈틱폰 방식의 릴레이 드로잉 콘텐츠이다. 모든 참여자가 동시에 얼굴을 그린 뒤 캔버스가 입장 순서 기준으로
다음 사람에게 전달되고, 몸통과 다리를 이어 그린다. 이전 파트의 하단 힌트만 보고 이어 그리기 때문에 결과는
예측 불가능하고 웃긴다.

N명이 참여하면 N개의 캐릭터가 탄생한다.

## 용어

- 게임: 방장이 게임 시작을 누른 뒤 최종 결과물이 생성될 때까지의 전체 흐름이다.
- 파트: 한 캐릭터를 구성하는 얼굴, 몸통, 다리 3개 단계를 의미한다.
- 캔버스: 최종 캐릭터 하나가 될 그림 묶음이다.
- 배정: 특정 참여자가 특정 파트에서 특정 캔버스를 그리도록 정해진 상태이다.

## 핵심 재미 요소

- 내 그림과 다른 사용자의 그림이 의도치 않게 합체되는 웃음
- 빠른 이해도와 낮은 진입장벽
- 결과가 강하게 남는 협업 경험
- 각 파트를 개별 메모지로 출력하고 합쳐 보는 구조

## 방 생성 및 참여

- 혼자서는 플레이할 수 없다.
- 최소 2명이 모여야 시작할 수 있다.
- 최대 인원은 6명이다.
- 최대 6개의 캐릭터가 생성된다.
- 방 생성 시 고유 방코드가 발급된다.
- 초대는 방코드, 공유 링크, QR 코드로 한다.
- 방 입장 시 닉네임을 입력해야 한다.
- 닉네임은 대기 화면, 게임 중 참여자 표시, 결과 화면에 사용된다.
- 닉네임 길이는 1~10자이며 빈 이름은 허용하지 않는다.
- 문자 종류는 제한하지 않는다. 한글, 영문, 숫자, 공백, 특수문자, 이모지를 모두 허용하며 길이만 검사한다.
- 닉네임은 최초 등록 시 저장되어 이후 다른 부스와 콘텐츠에서 자동 재사용된다.
- 대기 화면은 참여자 목록과 현재 인원을 실시간으로 표시한다.
- 방장은 인원을 확인한 후 게임을 시작한다.
- 방장은 게임 시작, 제한 시간 설정, 방 종료, 대기실 참여자 강퇴를 할 수 있다.
- 방장 강퇴는 대기실에서만 가능하며, 게임 시작 이후에는 강퇴할 수 없다.
- 방장은 가장 먼저 입장한 참여자이다.
- 방장이 이탈하면 입장 순서 기준 다음 참여자에게 자동 승계된다.
- 닉네임이 이미 등록된 사용자는 입장 시 닉네임 입력을 건너뛴다.
- 닉네임이 없는 사용자는 방 생성 또는 입장 전에 닉네임을 입력해야 한다.

## 방 식별 및 서버 상태 저장

- 방 식별자는 공유용 방코드인 `roomCode` 하나만 사용한다.
- 별도 내부 `roomId`는 두지 않는다.
- `roomCode`는 공유 링크, 실시간 연결 식별, Redis key에서 동일하게 사용한다.
- 방 대기 상태, 참여자 목록, 방장, 제한 시간, 현재 파트, 배정표, 제출 상태, 재접속 유예 정보는 Redis에 저장한다.
- Redis에는 이미지 바이너리를 저장하지 않고, 파트별 임시 이미지의 `fileId` 또는 MinIO object key 같은 참조값만 저장한다.
- PostgreSQL에는 게임 종료 후 최종 산출물과 갤러리 지급 결과만 저장한다.
- `artifact.source_room_id`에는 릴레이 방의 `roomCode`를 저장한다.

## 드로잉 제한 시간

- 방장은 게임 시작 전 제한 시간을 선택한다.
- 선택지는 30초, 45초, 60초이다.
- 각 파트별 드로잉에 동일한 제한 시간이 적용된다.
- 실시간 타이머를 표시한다.
- 제한 시간 초과 시 현재 상태 그대로 자동 제출된다.
- 제한 시간 초과 제출은 사용자가 제출 버튼을 누르지 않아도 클라이언트가 현재 캔버스를 자동 제출하는 방식이다.
- 빈 캔버스 상태에서 시간 초과해도 빈 상태로 제출된다.

## 파트 배정 및 패싱

- 게임 시작 시 입장 순서 기준으로 참여자 순서를 확정한다.
- N명이 참여하면 N개의 캔버스가 생성된다.
- 얼굴 파트에서는 각 참여자가 자기 순서의 캔버스를 그린다.
- 몸통 파트부터는 캔버스가 입장 순서 기준 다음 참여자에게 전달된다.
- 배정 공식은 `canvasIndex + partIndex`를 참여자 수로 나눈 나머지 위치의 참여자에게 배정하는 방식이다.
- `partIndex`는 얼굴 0, 몸통 1, 다리 2이다.
- 예를 들어 입장 순서가 `[A, B, C]`이면 `A`의 캔버스는 얼굴 `A`, 몸통 `B`, 다리 `C`가 그린다.
- 참여자가 이탈해도 게임 시작 시 확정된 배정표는 재계산하지 않는다.
- 이탈자가 이후 파트에서 그려야 했던 배정은 빈 그림으로 자동 제출한다.

## 드로잉 도구

- 펜/브러시: 자유 드로잉, 굵기 3단계
- 색상 팔레트: 기본 12색과 커스텀 색상
- 기본 12색: 검정, 빨강, 주황, 노랑, 초록, 파랑, 남색, 보라, 분홍, 갈색, 흰색, 회색
- 지우개: 터치/클릭 영역 삭제, 크기 조절 가능
- Undo: 최근 드로잉 동작 취소, 최대 20단계
- Redo: 되돌린 동작 재실행
- 페인트 채우기: 닫힌 영역 flood fill
- 획 지우개: 터치/클릭한 획 전체 삭제
- 전체 지우기: 확인 다이얼로그 후 캔버스 전체 삭제
- 컬러 드로잉을 지원하며 출력도 컬러 그대로 한다.

## 중도 이탈 처리

| 상황 | 처리 |
| --- | --- |
| 드로잉 중 이탈 | 그린 만큼 자동 제출, 빈 캔버스면 빈 상태 제출 |
| 대기 중 이탈 | 참여자 목록에서 즉시 제거, 2명 미만이면 시작 불가 |
| 대기 중 방장 이탈 | 입장 순서 기준 다음 참여자에게 방장 자동 승계 |
| 게임 중 방장 이탈 | 일반 참여자와 동일 처리, 권한은 남은 참여자 중 입장 순서 기준 가장 빠른 사람에게 승계 |
| 전원 이탈 | 방 자동 종료, 진행 중 결과물이 있으면 완성 가능한 파트까지만 저장 |
| 재접속 | 10초 이내 동일 `roomCode + UUID`로 재접속 시 복귀 가능 |

### 이탈자의 캔버스 처리

- 이탈자에게 배정된 캔버스는 그린 만큼 자동 제출한다.
- 빈 상태면 빈 상태로 제출한다.
- 이후 파트에서 이탈자 차례가 오면 해당 파트도 빈 상태로 자동 제출한다.
- 남은 참여자에게 이탈자의 파트를 재배정하지 않는다.
- 게임 시작 시 확정된 배정표를 유지한다.
- 이탈자가 담당한 파트는 비어 있는 상태로 완성된다.
- 이탈로 남은 인원이 2명 이하가 되어도 게임은 중단하지 않고 끝까지 진행한다.
- 2명이면 서로의 캔버스를 주고받으며 이어 그린다.

## 네트워크 끊김 대응

릴레이 드로잉은 실시간 멀티플레이이므로 `roomCode + UUID` 조합으로 재접속을 처리한다.

### 재접속 식별

- 방 입장 시 서버는 WebSocket 연결에 `roomCode + UUID`를 매핑한다.
- 방 URL에는 `roomCode`가 포함되어야 한다.
- UUID는 `localStorage + cookie` 이중 저장소에서 복구한다.
- 기존 참여자 목록에 `roomCode + UUID`가 있으면 세션 복귀로 처리한다.
- 없으면 신규 입장 또는 거부로 처리한다.

### 재접속 가능 여부

| 상황 | 복귀 | 정책 |
| --- | --- | --- |
| 네트워크 순단, 탭 유지 | 가능 | WebSocket 자동 재연결, UUID와 roomCode 유지 |
| 페이지 새로고침 | 조건부 가능 | UUID와 URL roomCode가 있으면 복귀 가능, 드로잉은 localStorage 임시 저장분만 복구 |
| 탭 닫기 후 링크 재진입 | 조건부 가능 | 10초 유예 시간 내 방 링크 재진입 시 가능 |
| 브라우저 캐시 삭제 | 불가 | UUID 소실 |

### 게임 중 입장 제어

- 기존 참여자 + 10초 이내: 복귀 허용
- 기존 참여자 + 10초 초과: 거부, “이미 자동 제출 처리되었습니다”
- 신규 UUID + 게임 진행 중: 차단, “게임이 진행 중입니다”
- 신규 UUID + 대기 중: 최대 인원 미만이면 입장 허용
- 중간 신규 합류는 캔버스 수와 참여자 수 불일치를 유발하므로 허용하지 않는다.

### 끊김 감지

- WebSocket heartbeat, `navigator.onLine`, ping 주기 체크로 감지한다.
- 끊김 시 “연결 끊김 — 재연결 중...” 오버레이를 표시한다.
- 드로잉 캔버스는 잠금 처리한다.
- 끊김 감지 즉시 현재 캔버스 데이터를 `roomCode + canvasId` 키로 localStorage에 임시 저장한다.
- 10초간 WebSocket 자동 재연결을 시도한다.
- 성공 시 `roomCode + UUID`로 복귀 요청 후 임시 저장 데이터를 동기화한다.
- 실패 시 중도 이탈과 동일하게 그린 만큼 자동 제출한다.
- 다른 참여자에게 닉네임 옆 “연결 불안정” 표시를 노출한다.

### 동일 UUID 중복 접속

- 서버는 `roomCode + UUID` 조합으로 활성 WebSocket 연결을 관리한다.
- 이미 활성 세션이 있는데 같은 조합으로 신규 연결이 오면 중복으로 판단한다.
- 기존 활성 세션을 강제 종료하고 신규 연결을 세션 복귀로 처리한다.
- 기존 클라이언트에는 “다른 곳에서 접속되어 연결이 종료되었습니다” 모달을 표시한다.
- UUID 복제나 멀티 어카운팅을 완벽히 막지는 못하지만 데이터 정합성 오류를 예방한다.

## 사용자 흐름

1. 방을 만들거나 공유 링크/QR로 입장한다.
2. 대기 화면에서 참여자를 확인한다.
3. 방장이 제한 시간을 설정하고 최소 2명이 모이면 시작한다.
4. 파트 1에서 모든 참여자가 얼굴을 그린다.
5. 캔버스가 입장 순서 기준 다음 참여자에게 전달되어 몸통을 그린다.
6. 다시 다음 참여자에게 전달되어 다리를 그린다.
7. 완성 캐릭터가 하나씩 공개된다.
8. 각 파트 메모지가 개별 출력되고 합체 연출을 보여준다.
9. 결과물을 저장, SNS 공유, 커뮤니티 벽 게시할 수 있다.

## 주요 기능

- 방코드, 공유 링크, QR 초대
- 얼굴, 몸통, 다리 3파트 릴레이
- 입장 순서 기준 순차 패싱
- 자신이 그린 캔버스를 연속으로 받지 않는 구조
- 이전 파트 하단 힌트 노출
- 제한 시간 타이머와 자동 제출
- 결과 캡처와 인스타그램 등 SNS 외부 공유
- 커뮤니티 게시 지원

## 출력 및 조합 방식

- 얼굴, 몸통, 다리를 각각 개별 메모지로 출력한다.
- 네모닉 출력물로는 하나로 합친 단일 이미지를 출력하지 않는다.
- 출력된 메모지들을 위에서 아래로 이어 붙이면 하나의 캐릭터가 완성된다.
- 화면에서는 파트별 메모지가 순차적으로 합쳐지는 애니메이션으로 공개한다.
- 갤러리와 공유에 사용할 저장용 최종 결과 이미지는 서버에서 별도로 합성한다.
- 이탈자가 담당한 파트는 빈 메모지로 출력된다.
- 빈 파트도 조합 구조에 포함된다.

## 임시 이미지 저장 및 정리

- 얼굴, 몸통, 다리 파트별 이미지는 게임 진행 중 힌트 제공과 최종 합성을 위한 임시 리소스이다.
- 파트별 임시 원본 이미지와 하단 힌트 이미지는 MinIO의 임시 경로에 저장한다.
- 권장 임시 경로는 `relay/tmp/{roomCode}/{canvasIndex}/{part}.png`이다.
- 하단 힌트 이미지를 별도로 저장하는 경우 권장 경로는 `relay/tmp/{roomCode}/{canvasIndex}/{part}-hint.png`이다.
- Redis에는 파트별 이미지의 object key, `fileId`, 제출자 UUID, 빈 제출 여부, 자동 제출 여부만 저장한다.
- 다음 파트를 그리는 참여자에게는 이전 파트의 전체 이미지가 아니라 하단 힌트 이미지만 제공한다.
- 최종 합성에는 MinIO 임시 경로에 저장된 파트별 원본 이미지를 사용한다.
- 정상 완료 시 최종 결과 원본과 썸네일을 영구 경로에 저장한 뒤 파트별 임시 이미지를 MinIO에서 하드 삭제한다.
- 중도 방 종료 또는 전원 이탈 시 저장 가능한 최종 결과물이 있으면 먼저 저장하고, 이후 임시 이미지를 하드 삭제한다.
- 삭제 대상은 `relay/tmp/` 아래의 파트별 원본 이미지와 힌트 이미지이다.
- 삭제 대상이 아닌 최종 결과물의 권장 경로는 `relay/results/{artifactId}/original.png`,
  `relay/results/{artifactId}/thumbnail.png`이다.
- 방 종료 시점의 즉시 삭제가 실패하거나 서버 장애로 임시 파일이 남을 수 있으므로 fallback 정리 정책을 둔다.
- fallback 정리는 `relay/tmp/` 아래에서 생성 후 24시간이 지난 object를 대상으로 한다.
- fallback 정리는 하루 1회 실행하는 것을 기본 정책으로 한다.
- Redis의 방 상태 TTL도 임시 이미지 정리 기준과 맞춰 24시간을 기본값으로 둔다.

## 결과물 소유권 및 생명주기

- 완성 결과물은 게임 종료 시점까지 남은 참여자의 UUID에 귀속된다.
- 중도 이탈자는 갤러리 지급 대상에서 제외된다.
- 잔류 참여자 UUID 목록을 DB에 저장한다.
- 합성된 최종 결과물 1건을 잔류 참여자의 갤러리에 동일하게 자동 보관한다.
- 결과물 이미지는 MinIO에 영구 저장된다.
- 메타데이터는 PostgreSQL에 저장된다.
- `artifact.thumbnail_url`은 갤러리와 목록 화면에 사용할 썸네일 이미지 URL이다.
- `relay_drawing_artifact.combined_preview_url`은 릴레이 드로잉 최종 결과물 원본 URL이다.
- 얼굴, 몸통, 다리 파트별 이미지 URL은 PostgreSQL 산출물 스키마에 저장하지 않는다.
- 갤러리 접근은 UUID가 살아 있을 때만 가능하다.
- 캐시 삭제로 UUID를 잃으면 갤러리 조회는 불가하지만 DB/MinIO 원본은 삭제되지 않는다.
- 릴레이 드로잉 전용 벽은 없다.
- 결과물은 커뮤니티 캔버스에 메모지로 게시할 수 있다.
- 같은 결과물을 여러 번 게시할 수 있다.
- 게시된 각 복사본은 커뮤니티 캔버스의 FIFO, 신고, 삭제 정책을 독립 적용받는다.
- 커뮤니티 게시 복사본이 FIFO로 제거되어도 MinIO/PostgreSQL 원본 결과물은 제거되지 않는다.

## 연출 포인트

- 파트 전환은 종이가 넘어가거나 접히는 모션으로 연출한다.
- 결과 공개는 메모지가 위에서 아래로 합쳐지는 합체 연출을 제공한다.
- 드로잉 시작음, 타이머 경고음, 합체 사운드 등 경쾌한 사운드를 사용한다.
- 대기 화면은 참여자 입장 시 캐릭터 실루엣이 하나씩 채워지는 모션을 제공한다.
