# 3. 오늘의 운세 뽑기

## 기획 의도

오늘의 운세 뽑기는 가장 낮은 진입 장벽으로 네모닉의 출력 경험을 제공하는 보조 핵심 콘텐츠이다.
복잡한 참여 과정 없이 즉시 결과를 받아볼 수 있으며, 개인적으로 소비하거나 커뮤니티 캔버스에 남길 수 있다.

## 핵심 재미 요소

- 기다림 없이 즉시 결과를 받는 재미
- 뽑기, 인쇄, 소지의 리듬감
- 운세 메시지로 반복 참여 유도

## 이용 제한

- UUID + 날짜(KST) 기준으로 하루 1회만 뽑을 수 있다.
- 일일 제한은 메모지 출력 성공 시점에만 차감한다.
- GMS 생성은 성공했지만 출력 단계에서 실패한 경우 다시 뽑기 재시도가 가능하다.
- 이미 오늘 뽑은 사용자가 재시도하면 “오늘의 오늘의 운세 뽑기는 이미 받았어요! 내일 다시 만나요” 안내를 표시한다.
- 제한은 자정(KST)에 초기화된다.
- 희소성을 통해 결과물 가치를 높이고 재방문을 유도한다.

## 입력 및 생성 방식

### 사용자 입력

- 생년월일시와 양력/음력 기준은 최초 1회만 입력받아 `app_user` 테이블에 영구 저장한다.
- 저장 컬럼은 `birthday`, `birthtime`, `is_lunar`를 사용한다.
- 최초 입력 화면에서는 생년월일시, 양력/음력 선택값을 `POST /api/v1/users/me/birthday`로 등록한다.
- 재방문 시에는 입력 단계를 건너뛰고 저장된 값을 재사용해 만세력 계산과 운세 생성으로 진입한다.
- 생년월일 수정이 필요하면 “내 정보 수정” 메뉴에서 갱신한다.
- UUID가 유효한 동안에만 저장된 생년월일시 정보를 재사용할 수 있다.
- 브라우저 캐시 삭제 등으로 UUID를 잃으면 새 UUID 기준으로 다시 등록해야 한다.
- 예: `1992-10-24 05:30`

### 프론트 만세력 계산

- 프론트엔드에서 만세력 계산 라이브러리로 사주 데이터를 계산한다.
- 계산 결과는 년주, 월주, 일주, 시주, 일간 오행, 일지 오행, 음양 정보 등을 포함한다.

예시:

```json
{
  "year": "임신",
  "month": "경술",
  "day": "계유",
  "hour": "을묘",
  "dayElemental": "수",
  "dayBranchElemental": "금",
  "dayYinYang": "음",
  "dayBranchYinYang": "음"
}
```

### 서버 GMS 해석

- 서버는 프론트에서 받은 사주 데이터를 GMS API에 프롬프트와 함께 전달한다.
- 운세 결과를 실시간 생성해 반환한다.
- 프롬프트 템플릿은 서버에서 관리한다.
- 백오피스에서 프롬프트 수정과 변경 이력 관리가 가능해야 한다.
- 생성된 결과는 DB에 저장한다.
- UUID + KST 날짜 기준 출력 성공 1회 제한을 적용한다.

서버 응답 예시:

```json
{
  "title": "오늘은 흐름을 정리하는 날",
  "summary": "감정적으로 밀어붙이기보다 차분하게 정리하고 우선순위를 세울수록 좋은 결과가 나는 하루입니다.",
  "overallLuck": 78,
  "loveLuck": 66,
  "workLuck": 84,
  "moneyLuck": 71,
  "luckyColor": "은회색",
  "luckyKeyword": "정리",
  "caution": "마음이 먼저 앞서면 흐름이 꼬일 수 있으니, 결정은 한 템포 늦추는 것이 좋습니다.",
  "postitLine": "오늘은 정리할수록 운이 열린다"
}
```

- `postitLine`은 네모닉 출력용 한 줄 요약이며 메모지에 크게 인쇄된다.

## GMS 실패 대응

- 운세 결과는 사주 기반 개인화 콘텐츠이므로 사전 생성 폴백 풀 방식은 적합하지 않다.
- GMS API 응답 지연 또는 실패 시 서버에서 최대 2회 자동 재시도한다.
- 재시도 후에도 실패하면 “운세를 가져오지 못했어요. 잠시 후 다시 시도해 주세요” 안내를 표시한다.
- 실패 시 다시 뽑기 버튼을 제공한다.
- 서버 오류로 인한 실패는 1일 1회 제한 횟수에서 차감하지 않는다.

## 사용자 흐름

1. 오늘의 운세 뽑기 부스에 진입한다.
2. 최초 방문이면 생년월일시와 양력/음력 기준을 등록하고, 재방문이면 저장된 값을 재사용한다.
3. 버튼 또는 레버 입력으로 뽑기를 요청한다.
4. 프론트에서 만세력을 계산해 서버로 전송한다.
5. 서버가 GMS API로 운세를 생성한다.
6. 네모닉이 메모지 형태로 출력한다.
7. 화면에서 사주 계산 결과와 운세 결과를 확인한다.
8. 메모를 소지하거나 커뮤니티 캔버스에 붙인다.

## 주요 기능

- 프론트 만세력 계산
- 서버 GMS API 운세 생성
- 결과 화면 표시
- UUID + 날짜 기준 1일 1회 제한
- 포춘 카드 디자인
- 일일 제한은 출력 성공 시점에만 차감
- 중복 운세 제어 항목은 삭제됨

## 결과물 저장 구조

운세 결과는 `fortune_artifact` 테이블에 구조화해 저장한다. 상세보기는 DB 데이터를 프론트가 직접 렌더링하고,
갤러리 썸네일용으로만 렌더링된 결과물 원본 이미지를 MinIO에 별도 저장한다.

| 컬럼 | 타입 | 저장 내용 |
| --- | --- | --- |
| `description` | `JSONB` | 운세 결과 본문과 사주 데이터, 디자인 메타데이터 전체 |
| `fortune_image_url` | `VARCHAR(200)` | 갤러리 썸네일용 원본 이미지의 MinIO 경로 |

`description` 예시:

```json
{
  "sajuYear": "임신",
  "sajuMonth": "경술",
  "sajuDay": "계유",
  "sajuHour": "을묘",
  "title": "오늘은 흐름을 정리하는 날",
  "summary": "감정적으로 밀어붙이기보다 차분하게 정리하고...",
  "overallLuck": 78,
  "loveLuck": 66,
  "workLuck": 84,
  "moneyLuck": 71,
  "luckyColor": "은회색",
  "luckyKeyword": "정리",
  "caution": "마음이 먼저 앞서면 흐름이 꼬일 수 있으니...",
  "postitLine": "오늘은 정리할수록 운이 열린다",
  "cardTheme": "moon",
  "bgColor": "#2C2C4A",
  "accentColor": "#C0C0C0",
  "iconKey": "moon_waning"
}
```

- `artifact.id`, `artifact.created_at`, `gallery.user_id` 등 메타데이터는 JSON에 넣지 않고 별도 컬럼/테이블에 저장한다.
- `cardTheme`, `bgColor`, `accentColor`, `iconKey` 등 디자인 에셋 키는 GMS 응답 또는 서버 로직에서 결정한다.
- 상세보기는 `description`의 JSON을 파싱해 프론트가 직접 렌더링한다.
- 갤러리 썸네일은 `fortune_image_url`이 가리키는 MinIO 원본 이미지를 사용한다.
- 커뮤니티 캔버스 게시 시에도 DB 데이터를 기반으로 프론트가 메모지를 렌더링한다.
- `overallLuck`, `loveLuck`, `workLuck`, `moneyLuck`은 0~100 정수여야 한다.
- `bgColor`, `accentColor`는 `#RRGGBB` 형식의 7자 hex 코드여야 한다.
- `caution`은 nullable이며, 그 외 필드는 서버 저장 전 NOT NULL로 검증한다.

## 소유권 및 생명주기

- 운세 결과 전체 문구, 수치, 에셋 키, 사주 데이터, 생성 시각, UUID는 DB에 영구 저장된다.
- 갤러리 썸네일용 원본 이미지는 MinIO에 영구 저장한다.
- 생성된 결과는 생성자의 갤러리에 자동 보관된다.
- 갤러리 조회 시 DB 데이터를 불러와 프론트가 렌더링한다.
- UUID가 유효한 동안에만 갤러리에서 조회할 수 있다.
- UUID를 잃으면 갤러리 조회는 불가능하지만 DB/MinIO 원본 결과는 삭제되지 않는다.
- 오늘의 운세 전용 벽은 없다.
- 갤러리에서 결과를 꺼내 커뮤니티 캔버스에 게시할 수 있다.
- 같은 운세 결과를 여러 번 게시할 수 있다.
- 게시된 각 메모 복사본은 독립적으로 FIFO, 신고, 삭제 정책을 적용받는다.
- 게시 메모에는 커뮤니티 캔버스의 50개 FIFO 정책이 동일하게 적용된다.

## 인터랙션 연출

- 버튼 누르기 또는 레버 당기기 같은 물리적 입력감을 제공한다.
- AI 생성 중 네모닉 프린터 작동 모션과 종이 급지음, 기계 진동을 재생한다.
- 출력 모션은 메모지가 프린터 슬롯에서 천천히 밀려 나오는 방식이다.
- 출력 사운드를 제공한다.
- 출력된 메모지를 뒤집거나 펼치며 문구가 드러나는 카드 공개 연출을 적용한다.
