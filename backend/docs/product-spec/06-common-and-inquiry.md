# 6. 공통 정책 및 고객 문의

## 공통 UUID 식별 체계

서비스는 회원가입과 로그인 없이 운영한다. 모든 콘텐츠는 클라이언트 측 익명 UUID를 기반으로 사용자를 식별한다.

| 항목 | 정책 |
| --- | --- |
| 식별자 생성 | 최초 방문 시 고유 UUID 생성 |
| 저장 | `localStorage + cookie` 이중 저장 |
| 적용 범위 | 커뮤니티, 릴레이, 플립북, 운세, 무한 캔버스, 갤러리 |
| 조회 조건 | UUID가 유효한 동안 본인 결과물 조회/수정 가능 |
| 교차 사용 | PC, 모바일, 브라우저가 다르면 UUID가 달라짐 |

- 한쪽 저장소가 삭제되어도 다른 저장소로 복구한다.
- UUID를 잃으면 본인 결과물 조회/수정 권한을 잃는다.
- 동일인 식별과 영구 차단에는 한계가 있다.

## 인앱 브라우저 대응

카카오톡, 인스타그램 등 인앱 브라우저는 스토리지 제약, WebSocket 불안정, 3D 성능 이슈가 있다.

| 항목 | 정책 |
| --- | --- |
| 감지 | User-Agent와 `window.opener` 등을 조합 |
| 안내 | “외부 브라우저에서 열어 주세요” 전체 화면 오버레이 |
| 안내 내용 | 열기 방법, 링크 복사 버튼 |
| 자동 리다이렉트 | iOS `x-safari-https://`, Android `intent://` 또는 Chrome Custom Tabs 시도 |
| 기능 차단 | 멀티플레이 기능 비활성화 |
| 허용 가능 | 감상성 단방향 기능은 가능하게 구분 |

- 릴레이 드로잉, 플립북, 무한 캔버스 등 WebSocket 멀티플레이 기능은 인앱에서 비활성화한다.
- 커뮤니티 캔버스 읽기, 오늘의 운세 등 단방향 기능은 가능하도록 구분한다.
- 인앱 브라우저의 저장소는 외부 브라우저와 분리될 수 있다.
- 외부 브라우저 이동 시 새 UUID가 발급될 수 있음을 안내한다.

## 동일 UUID 중복 접속 방지

멀티플레이 콘텐츠에 공통 적용한다.

| 콘텐츠 | 감지 기준 |
| --- | --- |
| 릴레이 드로잉 | `roomId + UUID` |
| 플립북 | `roomId + UUID` |
| 무한 캔버스 | `canvasId + UUID` |

정책:

- 서버는 활성 WebSocket 연결을 기준 조합으로 관리한다.
- 같은 기준 조합의 신규 연결이 들어오면 기존 활성 세션을 강제 종료한다.
- 신규 연결은 세션 복귀로 처리한다.
- 기존 클라이언트에는 “다른 곳에서 접속되어 연결이 종료되었습니다” 모달을 표시한다.
- UUID를 바꿔 다른 유저로 재입장하는 악의적 행위까지 완전히 막지는 못한다.
- 실수/단순 복제에 따른 중복 참여자 목록, 캔버스 소유권 충돌, 데이터 정합성 오류를 예방한다.

## 고객 문의 창구

서비스 이용 중 문의, 오류 신고, 개선 제안을 수집하는 단방향 문의 창구를 제공한다. 회원가입 없는 구조이므로
UUID와 선택 제공 이메일을 활용한다. 관리자는 백오피스에서 문의를 확인하고 답장 처리한다.

### 문의 제출 플로우

- 사이트 푸터 또는 설정 메뉴의 “고객 문의” 버튼에서 접근한다.
- 문의 유형을 드롭다운으로 선택한다.
- 유형: 오류 신고, 기능 제안, 컨텐츠 신고, 기타
- 본문은 자유 텍스트, 최대 1,000자
- 이메일은 선택 입력이다.
- 이메일이 없으면 답변은 불가하다.
- 첨부는 선택이며 스크린샷 등 이미지 파일을 최대 3개까지 허용한다.
- 첨부 파일은 10MB/개 제한이다.
- 첨부는 MinIO에 저장한다.
- 서버는 UUID, User-Agent, 디바이스/브라우저 정보, 현재 URL을 자동 수집한다.
- 개인식별정보는 수집하지 않는다.
- 스팸 방지로 동일 UUID 기준 분당 3건, 일 20건을 초과하면 rate limit한다.
- reCAPTCHA 등은 추후 검토한다.
- 제출 후 “문의가 접수되었습니다” 토스트를 표시한다.
- 답변 요청 시 예상 처리 기간을 함께 안내한다.

### 백오피스 문의 관리

- 전체 문의 목록을 생성일, 유형, 상태별로 필터링/정렬한다.
- 상세 확인을 원클릭으로 제공한다.
- 상태 워크플로우는 `new -> in_progress -> resolved/closed`이다.
- 상태 변경 이력은 감사 로그에 기록한다.
- 이메일이 제공된 문의에는 백오피스에서 직접 답장 이메일을 발송할 수 있다.
- 발송은 서버 SMTP 연동으로 처리한다.
- 컨텐츠 신고 유형 문의는 커뮤니티 캔버스/결과물 신고 시스템과 연계한다.
- 통계 대시보드는 유형별 문의 수, 평균 응답 시간, 미처리 건수를 제공한다.
- 문의 데이터는 영구 보관한다.
- 이메일 등 식별 가능 필드는 개인정보보호 법령에 따라 1년 후 자동 마스킹을 추후 검토한다.
