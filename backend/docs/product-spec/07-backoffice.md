# 7. 운영 시스템 백오피스

## 기획 의도

네모닉월드의 콘텐츠를 안정적으로 운영하기 위한 관리자 전용 웹 대시보드이다. 신고 처리, 콘텐츠 모니터링,
실시간 현황 확인, 시스템 파라미터 관리, 문의 처리, 감사 로그를 통합 제공한다.

회원가입 없는 익명 서비스 특성상 UUID 기반 콘텐츠 추적과 자동화된 신고 처리가 핵심이다.

## 조회 가능 화면

| 화면 | 조회 내용 |
| --- | --- |
| 대시보드 | 동시 접속자, 콘텐츠 활성 현황, 미처리 신고, 자동 숨김, 미처리 CS, 추이 차트, 전환율, WebSocket 연결, 유입 경로, 바이럴 지표, 평균 체류 시간 |
| 신고 관리 | 신고 1~4회 항목과 5회 자동 숨김 항목, 신고자 UUID와 사유/시각 |
| 커뮤니티 캔버스 | 활성 메모, FIFO 순위, 신고 횟수, 제거 임박 메모, UUID/시간 검색 |
| 릴레이/플립북 | 활성 방 메타데이터, 과거 방 이력, 내부 드로잉/미게시 결과물 열람 불가 |
| 무한 캔버스 | 활성 캔버스 메타데이터, 출력물 목록, 내부 드로잉/요소 열람 불가 |
| 오늘의 운세 | 발급 이력, 사주 4주, 운세 결과, GMS 프롬프트 템플릿, API 통계 |
| 통계 및 분석 | 접속자, 콘텐츠 참여, 시간대, 방 통계, 신고, 재방문, 이탈, Sankey 전환 |
| CS 문의 | 문의 목록, 처리 상태, UUID별 이력, 24시간 경보, 이메일 발송 이력 |
| 감사 로그 | 관리자 접속, 삭제, 복원, 설정 변경 등 모든 주요 조작 |

## 조작 가능 기능

- 신고 관리: 소프트 삭제
- 신고 관리: 일괄 소프트 삭제
- 신고 관리: 일괄 복원
- 커뮤니티 캔버스: 신고 5회 미만 메모 긴급 소프트 삭제
- 릴레이/플립북: 내부 드로잉을 보지 않고 메타데이터 기반 방 강제 종료
- 무한 캔버스: 내부 콘텐츠를 보지 않고 메타데이터 기반 캔버스 강제 종료
- CS 문의: 상태 변경, 내부 메모, 고객 이메일 회신
- 관리자 계정: 슈퍼 관리자만 관리자 생성/삭제 가능

커뮤니티 메모 등 DB에 보존되는 콘텐츠 삭제는 소프트 삭제이며 DB 영구 삭제는 제공하지 않는다. 무한 캔버스는 DB 레코드를 두지 않으므로
강제 종료 시 Redis 활성 상태만 evict한다.

## 변경 가능 설정

| 설정 | 기본값 | 영향 |
| --- | --- | --- |
| 커뮤니티 캔버스 최대 메모 수 | 50개 | 즉시 적용, 초과 시 FIFO |
| 신고 자동 숨김 기준 | 5회 | 이후 신고부터 적용 |
| 릴레이 인원 | 2~6명 | 신규 방부터 적용 |
| 플립북 인원 | 2~12명 | 신규 방부터 적용 |
| 무한 캔버스 최소/최대 인원 | 1~6명 | 신규 캔버스부터 적용, 서버 안정성 검증 후 최대 10명 확장 가능 |
| 무한 캔버스 만료 정책 | 전원 이탈 즉시 | 릴레이/플립북 10초 grace와 비활동 TTL은 적용하지 않음 |
| 오늘의 운세 일일 제한 | 1회 | 즉시 적용 |
| GMS 프롬프트 템플릿 | 운영 설정 | 변경 이력 기록 |
| CS 문의 경보 기준 | 24시간 | 대시보드 경보 배지 |

- 모든 설정 변경 시 변경 사유를 입력해야 한다.
- 모든 변경은 감사 로그에 기록한다.
- 서비스 재시작 없이 실시간 반영한다.
- 슈퍼 관리자는 모든 기능과 관리자 계정 관리가 가능하다.
- 일반 관리자는 콘텐츠 관리, 신고 처리, 모니터링만 접근한다.

## 접근 권한

- 백오피스는 운영자 계정으로만 접근한다.
- 일반 사용자에게 노출하지 않는다.
- 별도 관리자 URL, 예: `admin.nemonicworld.com`
- 인증은 운영자 계정 아이디/비밀번호 방식이다.
- 일반 사용자 UUID 인증과 완전히 별개이다.
- 권한 등급은 슈퍼 관리자와 일반 관리자이다.
- 모든 관리자 접속과 주요 조작은 감사 로그로 기록한다.

6연결로 부하 관점에서 동등하다.

## 신고 및 콘텐츠 관리

### 신고 목록

- 전체 신고 내역 최신순 조회
- 신고 1회부터 5회 이상까지 모두 조회
- 숨김 전 단계 1~4회도 모니터링 가능
- 신고 횟수 구간 필터 제공
- 상태별 필터: 미처리, 자동 숨김, 복원, 소프트 삭제
- 신고 사유별, 날짜별 필터
- 5회 누적 자동 숨김은 “자동 숨김” 라벨
- 1~4회는 “주의” 라벨
- 신고자 UUID 목록, 사유, 시각 조회

### 운영자 조치

- 악성 신고는 `is_hidden = false`로 복원한다.
- 복원 시 50개 초과가 가능하며 다음 CREATE 시 FIFO가 정리한다.
- 부적절 콘텐츠는 `deleted_at`, `deleted_reason = admin_removed`로 소프트 삭제한다.
- 여러 신고 건을 선택해 일괄 소프트 삭제 또는 일괄 복원한다.
- DB 영구 삭제는 제공하지 않는다.
- 결정 시각과 담당 운영자를 감사 로그에 기록한다.

### AI 모더레이션 로그

- AI 모더레이션으로 자동 숨김된 메모 로그를 조회한다.
- 로그는 UUID, 원본 이미지, OCR 추출 텍스트, 감지 카테고리, 부착 시각, 검사 완료 시각, 검사 지연 시간을 포함한다.
- `hidden_reason`으로 `ai_moderation`과 `report_threshold`를 구분한다.
- 검사 지연 평균/P95를 추적한다.
- 예: P95 > 30초 시 알림
- 운영자가 오탐이면 복원, 실제 부적절이면 소프트 삭제한다.

## 커뮤니티 캔버스 관리

- 활성 메모 최대 50개 목록 조회
- 내용 미리보기, 작성 시각, 부착 순서, FIFO 순위, 신고 횟수 표시
- UUID와 작성 시간 범위로 검색
- 신고 5회 미달이어도 긴급 소프트 삭제 가능
- 가장 오래된 5개를 제거 임박 메모로 표시
- 시간 기반 소멸 예측은 적용하지 않는다.

## 릴레이 드로잉 / 플립북 관리

- 진행 중 방은 참여자끼리의 사적 공간이다.
- 운영자는 진행 중 방의 라운드별 드로잉을 열람하지 않는다.
- 완성된 미게시 결과물도 열람하거나 삭제할 수 없다.
- 커뮤니티 벽에 게시된 결과물만 커뮤니티 캔버스 메모로 관리한다.
- 활성 방 목록은 방코드, 참여 인원, 현재 라운드, 상태, 마지막 라운드 진행 시각, WebSocket 연결 수, 방장 이탈 여부를 표시한다.
- 좀비방은 메타데이터 기반으로 식별한다.
- 예: 참여 인원 0명, 마지막 라운드 진행 후 장시간 미진행, 대기방 최소 인원 이하 장시간 정지
- 운영자는 내부 드로잉을 보지 않고 방 강제 종료 가능하다.
- 강제 종료 사유는 좀비방 정리, 외부 신고 대응, 기타 등으로 선택/입력한다.
- 과거 방 이력은 참여 인원, 소요 시간, 결과물 수, 완주 여부, 종료 사유 등 메타데이터만 제공한다.

## 무한 캔버스 관리

- 무한 캔버스는 공유 링크로만 접근 가능한 사적 협업 공간이다.
- 별도 신고 기능은 두지 않는다.
- 운영자는 내부 드로잉/요소를 어떤 경우에도 열람하지 않는다.
- 열람 UI/API를 제공하지 않는다.
- 외부 제보/신고가 들어오면 캡처/링크 등 신고된 증거만으로 강제 종료를 판단한다.
- 활성 캔버스 목록은 URL, 접속자 수, 마지막 활동 시각, 생성 시각을 표시한다.
- 만료 예정 시각 컬럼은 두지 않는다.
- 참여자 전원이 이탈하면 즉시 자동 만료된다.
- 새로고침, 탭 닫기, 네트워크 순단도 활성 연결 0이 되면 만료 대상이다.
- 릴레이/플립북의 10초 grace는 적용하지 않는다.
- 비활동 기반 만료도 두지 않는다.
- Redis 작업물과 활성 캔버스 메타데이터는 즉시 evict한다.
- DB에는 캔버스 레코드를 별도로 두지 않는다.
- 백오피스와 감사 로그에는 캔버스 자체 메타데이터가 아니라 운영자 강제 종료 같은 조작 이력만 기록한다.
- WebSocket disconnect 감지 실패 등 비정상 좀비방만 메타데이터로 식별한다.
- 출력 포스트잇은 사용자 산출물이므로 관리자가 삭제할 수 없다.
- 커뮤니티 벽 게시본은 커뮤니티 캔버스 관리에서 처리한다.

### 중도 이탈률

| 콘텐츠 | 이탈 기준 | 퍼널 |
| --- | --- | --- |
| 릴레이 | 방 입장 후 결과 공개 전 이탈 | 방 입장, 대기 완료, 라운드별 완료, 결과 공개 |
| 플립북 | 방 입장 후 마지막 라운드 전 이탈 | 방 입장, 대기 완료, 라운드별 완료, 결과 공개 |
| 무한 캔버스 | 입장 후 드로잉/출력 없이 N분 내 이탈 | 입장, 첫 요소, 5분 활동, 출력 |
| 커뮤니티 | 존 진입 후 메모 부착 없이 이탈 | 진입, 작성 시작, 출력, 부착 |
| 운세 | 부스 진입 후 뽑기 완료 없이 이탈 | 진입, 요청, 결과 확인 |

- 단계별 전환율과 이탈률을 계산한다.
- 평균 체류 시간을 측정한다.
- 자발적 이탈과 비자발적 이탈을 구분한다.
- `navigator.sendBeacon()`으로 자발적 이탈 이벤트를 보낸다.
- WebSocket heartbeat timeout은 비자발적 이탈로 추정한다.
- OpenSearch Dashboards에서 퍼널 시각화를 구성한다.

### 콘텐츠 간 전환율

- `zone_enter` 이벤트에 `prev_zone`을 추가한다.
- 최초 진입은 `prev_zone = lobby`로 기록한다.
- Sankey diagram으로 콘텐츠 간 이동 흐름을 시각화한다.
- 콘텐츠별 유입 경로 비율을 제공한다.
- 콘텐츠별 이탈 후 행선지를 추적한다.
- 인기 동선 Top N을 제공한다.
- 콘텐츠 배치 최적화, 안내 동선 설계, 이벤트 효과 측정에 활용한다.

## 알림 및 자동화

- 자동 숨김 발생 시 운영자에게 실시간 알림

- 오늘의 운세 GMS API 최종 실패율 초과 알림
- 재시도율 급등 경보
- API/WebSocket/DB/MinIO 등 주요 인프라 상태 모니터링
- 일별/주별 운영 요약 리포트 자동 생성

## 데스크톱 앱 운영

네모닉월드는 향후 Electron 기반 개인용 데스크톱 앱으로 배포된다.

### 도입 근거

- 프린터 직접 출력: `webContents.print()`로 다이얼로그 없이 즉시 출력
- 데스크톱 통합: 시스템 트레이, 글로벌 단축키, OS 네이티브 알림
- 오프라인 회복력: 작성 메모를 로컬 임시 큐에 보관 후 재연결 시 전송
- 자동 업데이트: `electron-updater`
- 로컬 진단 로그: `electron-log`, 사용자 동의 하 익명 전송
- 보안: `nodeIntegration: false`, `contextIsolation: true`, preload 스크립트로 API 제한

### 백오피스 연계

- 설치 통계: OS별/버전별 분포
- 업데이트 배포: stable/beta 채널 관리, 적용률, 롤백
- 크래쉬/오류 집계
- 자동 업데이트 성공률/실패 사유
- 개별 단말 위치/식별 정보는 수집하지 않는다.
- 원격 명령, 스크린샷 전송 같은 감시성 기능은 제공하지 않는다.

### 배포 전략

- Windows `.exe`, macOS `.dmg`, Linux `.AppImage`
- Windows SmartScreen 경고 방지를 위한 코드 서명
- Main, Renderer, Preload 구조
- React 코드는 웹 버전과 재사용
- `process.versions.electron`으로 런타임 감지
- 업데이트 배포 채널 변경과 새 버전 배포는 감사 로그에 기록

## 운영자 실시간 알림

백오피스 내부 Web Push, Service Worker, SSE, 인앱 배지는 사용하지 않는다. 운영 동선을 Mattermost 중심으로 단일화하고,
이메일을 병행한다.

### 알림 채널

- Mattermost Incoming Webhook
- 네모닉 자체 이메일 SMTP

### 이벤트

| 이벤트 | 심각도 | 정책 |
| --- | --- | --- |
| 자동 숨김 발생 | Warning | `hidden_reason` 포함 |
| 신규 CS 문의 | Info | 접수 즉시 |
| CS 24시간 미처리 | Warning | 1시간 간격 리마인드 |
| GMS 최종 실패율 초과 | Critical | 이메일까지 전송 |
| 서버 다운 | Critical | 이메일까지 전송 |
| 동시 접속 임계치 초과 | Warning | WebSocket 연결 기준 |

### 구현 정책

- Mattermost 채널은 용도별 분리한다.
- 예: `#nemonic-alerts`, `#nemonic-alerts-critical`, `#nemonic-cs`
- 메시지에는 이벤트 요약, 대상 링크, 심각도 배지를 포함한다.
- SMTP는 운영자 메일 그룹으로 발송한다.
- Critical 이벤트는 반드시 이메일까지 이중 전달한다.
- 관리자별로 심각도별 수신 채널을 설정할 수 있다.
- 전송 실패 시 지수 백오프로 최대 3회 재시도한다.
- 한 채널 실패 시 반대 채널로 폴백한다.
- 동일 이벤트 ID 기준 5분 dedup 윈도우를 적용한다.
- Critical은 의도적 이중 전달을 유지한다.
- Webhook URL과 SMTP 자격 증명은 Vault/K8s Secret으로 관리한다.
- 감사 로그에는 URL 원문 대신 채널명만 남긴다.
- 모든 알림 발송 이력은 감사 로그에 기록한다.
